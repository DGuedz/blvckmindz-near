# Demo review — 14 November 2026

[Open the demo](https://blvckmindz-near-demo.vercel.app/) · [Reopen the reviewed payment](https://blvckmindz-near-demo.vercel.app/?run=76cd07e4-95f0-4477-8a79-becaacf31538)

The reviewed path is a fixed recording invoice: **2.00 test tokens → 0.80 label / 0.84 artist / 0.36 beatmaker**. An ISRC identifies the recording; the agreed terms determine the shares. Sample recipients and agreements are demonstration data.

## What the evaluator does

1. **Open the prefilled sheet.** The recording sample is ready. Participant details and the calculation remain available on demand.
2. **Simulate split.** Sheet → agreement → allocation → result. This calculation runs locally and moves no tokens. The next action appears beside the result.
3. **Distribute on testnet.** The server reserves a fresh batch, funds the invoice, approves the fixed sample and requests distribution. The animation follows reported execution stages. It is an explanation of those stages, not a measurement of network latency.
4. **Verify the receipt.** “Received” appears only after the payout transaction, configured contracts, batch, recipients, amounts and transfer events match. The link opens that run's transaction. Reload and “View verified receipt” read the same request without paying again.

## Corrections and checks

| Area | Correction | Validation |
|---|---|---|
| Repeated clicks | A shared in-flight operation, persisted request ID and process lock prevent a second payout for the same intent. | Public UI double click produced one run; 50 concurrent local retries used one executor. |
| Reload / lost response | URL bookmark and best-effort session storage preserve the request. Recovery reads first; retry after an explicit 404 uses the same ID. | Reload, refused POST, missing request, lost response and blocked storage exercised in an isolated UI harness. |
| Interrupted execution | Unknown transaction results and evidence-export failures require operator review before another run. | Persisted state, process contention, orphan locks and export-failure tests. |
| Proof authenticity | RPC receipt executor takes precedence over fields inside a parsed log. UI rejects inconsistent proof instead of showing “Received”. | Spoofed event-emitter regressions and a deliberately inconsistent UI fixture. |
| Changing the case | Fields, presets and lookup actions stay locked during execution. A new test requires an explicit action. | Public execution and local cancellation / slow-lookup checks. |
| Public HTTP | Opt-in public mode, exact configured Host/Origin, fixed templates, small JSON body, generic errors and response security headers. | HTTP-policy tests; public Vercel execution. Origin checks constrain browser requests; they are not authentication. |
| Amounts and layout | Integer arithmetic, bounded input length and abbreviated diagram values with exact amounts in details. | 1,000 deterministic sheets; 320px mobile and 1280px desktop inspections, including the largest accepted amount. No horizontal page overflow observed at those widths. |

The application suite passed **101 tests**. The 1,000 calculation vectors and concurrent retries above are local test cases, not additional on-chain payments. Rust source was unchanged in this review; earlier contract/integration test results are not represented as a fresh run here. The historical “43 checks” belongs to the archived deployment.

UI fault fixtures are visibly labelled, use no signing keys and send no chain transactions. Their screenshots and logs demonstrate error handling, not payment evidence. CSS includes reduced-motion behavior; this review is not a complete accessibility conformance audit.

The public candidate is copied from an explicit file list, without `.keys`, `.env`, dependency folders, private documentation or Git history. The default secret scanner produced four generic-key alerts: each was a 32-byte public Solana token-account address in the independently checked transaction. All four were reviewed; no credential was identified in this set. [Recorded classifications](../evidence/SECRET-REVIEW.json). This does not clear the separate private parent repository or its history for publication.

## Hosting and remaining boundaries

The public URL is a Vercel proxy to a temporary Cloudflare tunnel and this Mac's Node process. Only two façade files were deployed to Vercel; no signing keys were uploaded. The Mac, network connection, Node process and tunnel must remain available. A replacement tunnel requires updating and redeploying the façade. This is not an independent server deployment.

The public operator sponsors at most ten fixed sample runs across the persisted book. Public access can exhaust this small test budget. Existing receipt reads and local simulations do not consume a new run. It is not an authenticated artist payout service.

The token is a project-issued, valueless test token, not Circle USDC. This demo does not prove commercial settlement, legal ownership, human agreement collection, an email-login journey, cash-out or mainnet readiness. The existing confirmed sample rights are reused; the juror is testing invoice execution rather than signing a new rights agreement.

The NEAR / Solana portal exposes independent test receipts. The Solana reference is historical and was rechecked on 14 November. Its terms differ from this NEAR sample. [No bridge or cross-chain settlement is implemented](network-boundary.md).
